# PBE local restore implementation contract

Approved implementation design for Task D3, September 12, 2026. **Not implemented or verified; no import command is ready to run.** Final D1/D2 mappings and populated tests remain prerequisites. This document refines the [release operations](pbe-training.md) and [D3 plan](../superpowers/plans/2026-09-12-pbe-chapter-progress.md).

## Supported scope and limits of the claim

Build a managed local offline importer for complete, bounded, declared source bundles. Initial operational authority support is terminal, drained PBE Rooms in Completed or Interrupted state. Support canonical offline SQLite and explicitly inventoried native local sources/fixtures, preserving all dependencies and original source archives in the declared scope. A selected-room fixture is permitted only with a trustworthy exhaustive inventory for that declared scope; it is not a whole-source migration. No source data may be silently excluded to fit a cap.

Unsupported active clocks, Lobby/Playing/Abandoned authority, undrained Room/Solo outboxes, unsupported timed Solo authority, unsupported legacy operational Room authority, unknown mappings or incomplete native namespace inventory must fail before target initialization or data writes. Keep the entire original backup. A completed Simulation can still own timing authority and must not be admitted merely because its recap is complete. Current source lacks enough portable historical timing metadata to fabricate equivalent authority safely.

These boundaries are explicit limitations of the first local tool, not a waiver of required populated PBE history, retry, non-timed Solo correction, Room dispute, chapter projection, B4 and legacy Memory-session restore tests. Report supported selected-scope proof separately from complete-source migration. Generic hosted/native backup inventory and live restoration remain unsupported external work; do not represent a D1 export as the whole authority backup.

## Minimal implementation surface

- `scripts/cloudflare-import.mjs`: only `--bundle <private-dir> --local <dedicated-persist-dir>`, complete preflight and same-bundle resumable coordination. No remote/account URL, arbitrary table/SQL action or automatic application activation.
- `scripts/lib/cloudflare-bound-bundle.mjs`: versioned inventory, exact archives/chunks, explicit known mappings, counts, disposable SQLite validation and deterministic import plan. Preserve the existing literal-SQL exporter guard.
- `scripts/lib/cloudflare-maintenance-local.mjs`: one owned Miniflare instance, pinned identity/build/schema, fixed D1 and four existing DO bindings, exclusive managed local lifecycle. No `test-runtime.ts` import or undocumented backing-file edits.
- `apps/web/worker/native/maintenance/index.ts` and `protocol.ts`: separate closed entrypoint re-exporting real DO classes, fixed v1 schemas and bounded operations. Inbound fetch always404; no assets, API router or socket proxy.
- Narrow private maintenance handlers in real Room/Reports classes using their normal storage, plus offline event guards in Room/Reports/Solo. The binding setting `NATIVE_MAINTENANCE_MODE:'offline-v1'` is not request controlled. Normal production dispatch must never forward `/__maintenance/v1/*`; production config lacks the mode setting.
- A small additive maintenance receipt table, distinct from organization Records, pins the complete bundle, target, mapping, migrations and build. Exact archive identities include table plus complete primary key; PBE includes `[OrganizationId,Kind,Id]` with opaque case preserved.

Local transport uses Miniflare `getD1Database` for fixed parameterized statements and `getDurableObjectNamespace` for binding fetches to allowlisted operations. This is a supported local binding mechanism, not a deployed maintenance endpoint. [Miniflare documentation](https://developers.cloudflare.com/workers/testing/miniflare/storage/durable-objects/)

Room operations cover inspect/capture roots and node pages, restore begin/stage/verify/commit/receipt. Reports captures/imports bounded scoped bookkeeping. Unknown operation, wrong mode/scope/ticket or differing existing bytes fails. No general raw-state setter, public admin route or new historical product fallback is part of this work.

## Quiescence, atomicity and resumption

1. Drain the compatible source normally, then stop its owned host/tickers/runtime completely. Use a consistent canonical SQLite backup including WAL semantics; native capture restarts the same pinned persistence only in the closed maintenance entrypoint. Do not kill unrelated hosts or infer completion from Team Practice being disabled.
2. Guard constructors, fetch, alarms, socket handlers and every projection/scheduling path before application work. Process restart removes old in-memory continuations; all captured outbox/history/component checks must still agree. `getAlarm() === null` does not prove no handler is executing, and deleting an alarm does not guarantee cancellation of its running handler. [Alarm documentation](https://developers.cloudflare.com/durable-objects/api/alarms/)
3. Pin exact authority/outbox/history roots, complete retained components and Reports state; read bounded pages and recheck roots/inventories at capture end. Retain superseded nodes. D1's asynchronously projected room directory cannot establish complete native DO inventory; require explicit authoritative inventory rather than invented namespace enumeration.
4. Validate the complete immutable bundle before creating the destination. Stream-verify hashes, bytes, composite identities, scalar precision, mappings, source relationships and every cap. Use an isolated validation DB with all accepted migrations and FK checks. Unknown or incomplete data fails the entire declared bundle.
5. Open only the closed runtime over a new private target. D1 writes use fixed bound parameters and full-field readback; stage exact Room nodes under a pinned ticket. Existing identical data is a no-op; conflicting data halts without overwriting. Resume the same bundle/build/target/schema only.
6. Verify closures incrementally, then atomically commit supplied Room state plus receipt with absent outbox. Do not call save/recover/grade/project or fabricate projection acknowledgement. SQLite DO transactions use storage APIs, including synchronous callbacks for `transactionSync`. [Storage documentation](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/)
7. There is no transaction across DO and D1. The global receipt and managed closed startup remain in force until every row/object has exact readback. Lost acknowledgements resolve by readback; never reset completed objects or delete partial source history. The managed local fence does not claim to stop a person launching arbitrary incompatible code directly on that directory.
8. Certify exact bytes before activation. Run authenticated operational tests on a disposable verified destination after stopping the closed runtime; ordinary GET may then legitimately update an epoch/projection. This later behavior is distinct from original-byte restoration. Never automatically activate a real destination or deploy.

## Operating caps

All MiB are1,048,576bytes. These approved initial importer/capture caps must be implemented and tested together; they do not reduce ordinary authoring or study admission. A failed required complete fixture may justify a new measured design ruling, never silent truncation or an unrecorded cap increase.

| Dimension | Initial v1 cap and accounting |
|---|---|
| Room count | 4 terminal PBE Rooms per complete bundle, across all organizations/seasons combined. Other source data remains complete. Room five rejects the declared bundle; no silent selection. An explicitly declared selected-room scope is allowed only with trusted exhaustive inventory and complete dependencies, and cannot be reported as whole-source migration. |
| Decoded native Room/history | 8 MiB for each full reconstructed authority and terminal projection; precheck sum of logical component ref bytes plus reconstruction overhead, then check exact reconstructed bytes. Decode at most one room/root at once. This bounds serialized bytes, not JS heap amplification. |
| Canonical room/source row | 16 MiB for actual canonical `StateJson`; 32 MiB for any complete original source-row archive encoding. Both are independently checked. No assumption that PascalCase wrapper bytes equal native bytes. |
| Reachable component closure | At most 2,048 unique nodes and 64 MiB serialized node `data` per authority/history closure; maximum branch depth 16 and 8,192 traversed edges per decode. Bound reference expansion as well as unique hashes so a shared DAG cannot cause unbounded repeated traversal. Reject cycles and every length/hash/scope mismatch. |
| Full retained inventory | At most 2,048 rows / 64 MiB node payload in the Room DO, and separately the same cap in that room's scoped D1 components. Count all rows, including superseded metadata; preserve their supplied bytes. Aggregate root/receipt/Reports data is counted separately below. |
| Whole bundle | 512 MiB actual sum of finalized file bytes, including original SQLite backup if included, archives, duplicate store payloads, mapping rows, manifests and bookkeeping; no compressed-size shortcut. Maximum 100,000 target D1 rows including archive chunks. |
| Planned stored payload | D1 sum of all encoded row values plus 4,096 bytes allowance per row ≤128 MiB; all DO captured/imported table payloads including Reports ≤256 MiB. These are payload admission limits, not physical SQLite size measurements; indexes/pages/WAL and runtime storage overhead remain separate. |
| Reports bookkeeping | ≤4,096 captured publication/verification rows and ≤16 MiB payload per organization/season Reports object; ≤4 Reports scopes total. Larger bookkeeping rejects a complete capture, even if the latest room closure fits. |
| Operational D1 row | Existing preflight cap: encoded values plus 4,096-byte allowance ≤1,000,000 bytes, each value independently checked. A normal authoring record larger than this is explicitly unsupported by v1 import; do not chunk an operational value unless its accepted product schema already supports it. |
| SQL / parameters | ≤100,000 UTF-8 bytes per fixed statement; ≤100 parameters. Normal row write/readback uses one row and one statement per call. Null uses actual null through the local binding; integer fields must round-trip losslessly. Existing literal-SQL export still refuses oversized statements. |
| D1 transport body/readback | ≤1,500,000 actual serialized wire bytes per mutation/readback page. Precompute even for local proxy transport; limit is an application admission bound, not a claimed REST body limit. Large rows read singly. |
| DO stage/capture/verify page | ≤8 component nodes AND ≤1,048,576 actual serialized request/response bytes, whichever stops the page first. A node that cannot fit alone fails preflight. Each node also satisfies existing `parseNode`: encoded node bytes <1 MiB and leaf content ≤128 KiB. Do not assume eight arbitrary escaped leaves fit. Manifest retains existing ≤128 KiB cap. |
| Key / bookkeeping pages | ≤100 keys and ≤64 KiB serialized identity response. Data rows individually read, or ≤8 small bookkeeping rows within the same 1 MiB envelope. A resume cursor contains scope/generation/last key, not a trusted completion count. |
| Per invocation / segment | One adapter call in flight; DO verification continuation ≤8 nodes and ≤16 D1 statements; retain ordinary authenticated request limit 50 total D1 statements including auth/guards. CLI checkpoints after 1,000 rows/nodes or 32 MiB cumulative request bodies, whichever first, then exits resumably. Counters cover retries; stop after 3 transient retries per operation, do not retry conflicts/auth/schema failures. |
| Source archive chunk | At most 65,536 raw bytes per chunk, base64 stored in bounded archive rows; ≤512 chunks per 32 MiB source row. Ordered chunk hashes/lengths and whole-original hash are required. Exact reassembly precedes acceptance. |


The ordinary measured471-node/17,086,239-byte and stress1,019-node/52,446,415-byte retained inventories individually fit the per-store caps. Their complete bundles, including all archives and Reports state, still need measurement. Four stress rooms cannot fit the total D1 payload cap; all caps apply simultaneously. Serialized payload bounds do not certify physical SQLite size, JS heap, account capacity or restore time.

The stricter local payload caps leave headroom without proving hosted execution. [D1 limits](https://developers.cloudflare.com/d1/platform/limits/)

## Required preservation and acceptance

Preserve actual native authority roots/nodes and canonical explicit mappings for frozen questions/reserves/replacements, roster/roles, original command and attempt IDs, actor-owned retries, locks/timing/presentation, services/sequences, owner/coach, rules and source proofs. `AppliedCommands` maps explicitly to native `applied`; stripped history cannot recreate it. Verify the exact original terminal command retry before any ordinary GET that may recover an epoch.

Preserve operational D1 records and every original row separately. Original JSON strings, dictionary keys, scalar fields, revisions and composite identities remain exact; oversized original archives use ordered byte chunks with per-chunk and whole hashes. Do not camel-case arbitrary dictionaries, regrade, repair IDs or normalize original text. B4 indexed raw answers/empties/order and saved results remain unchanged. Final D1/D2 stamp/proof/replay/continuation mappings are binding inputs once accepted.

Pending/resolved disputes require their complete evidence/ref/index/dirty/replay/overlay/adjustment/discovery graph. Non-timed Solo and terminal Room correction replay must resume without duplicate adjustments. Copied upload/verification flags are not readback evidence. Canonical sources can initialize empty native Reports bookkeeping only after independently validating operational history/awards; never blanket-republish to conceal mapping errors.

D3 must produce actual failing-then-passing populated mapping tests, composite-key/raw-byte archive tests, canonical Completed/Interrupted full-room conversion, ordinary/stress native declared-scope capture/restore, terminal retry and authorization, pending/resolved correction continuation, B4 and legacy Memory resume. Test public maintenance denial, offline delivered alarms/sockets, malformed/cyclic/oversized closure, every numeric boundary, mismatched identity/digest, lost stage/D1/root acknowledgements, interrupted multi-room import and same-bundle restart. Measure complete authenticated request cost separately from maintenance pages. Unknown inventory and unsupported timed/active authority must have honest no-target-write negative tests. No live pilot, complete hosted backup or deployment success follows from these local gates.
