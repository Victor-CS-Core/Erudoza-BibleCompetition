## Student outcome and standards boundary

Students practice the selected season's personally assigned material using source-backed factual, list and exact-word questions. Team rehearsal uses the coach-approved season through private room membership. A team result does not establish that each participant can recall the answer independently.

The independent mode permits students to start, finish and replay without an adult online. Each ordinary answer receives automatic rubric grading. C3 adds later coach review of flagged answers, preserving the original answer, automatic grade and response time. A flag must not grant points or block ordinary progression.

The [NAD resource page](https://nadpbe.org/pbe-resources/) was rechecked on September 12, 2026. It still linked the [2023–24 PBE guide](https://nadpbe.org/wp-content/uploads/2023/11/How-to-Bible-Experience-2023-24.pdf), listed the 2026–27 books and described the new study resources as forthcoming. The implemented baseline follows the linked guide's referenced questions, two readings, 1–8-point response timing, accuracy scoring, teams of 2–6, and full 90-question rehearsal with a five-minute break after question 45. The app does not derive official placing from its own percentage or head-to-head score. Actual cohort rules, source edition and conference variations require confirmation before enabling that cohort.

The eight-question daily mix, 1/3/7/14-day review intervals, 48-hour chapter-proof threshold, reserve count and numeric true/false cap are Erudoza design choices. They are not presented as official PBE requirements or proven optimal learning intervals. Ten-question solo Simulation and 10/30-question team sets are labeled shortened practice. Audio is optional; the labeled text fallback records different delivery evidence.

## Timing, persistence and recovery

Native solo timing lives in the `PBE_SOLO` Durable Object, with additive `v3-pbe-solo` configuration. Team timing lives in the existing Room Durable Object. Authoritative state and an immutable projection outbox are saved before acknowledgement. D1 session/room/history projections alone do not constitute a backup of a just-locked answer whose delivery is pending.

The canonical backend uses a monotonic timing authority and persisted session/room outbox records. Complete bounded request receipt precedes timing admission. After unrecoverable armed-clock loss, trustworthy saved answers settle; otherwise practice interrupts, retaining earlier evidence and offering restart. UTC timestamps are not used to open a replacement scoring window.

Original response lock time and original acceptance sequence are distinct. A coach correction or delayed outbox delivery must not become a new retrieval. C3 and D1 must preserve this distinction when replaying adjusted evidence and checking delayed recall.

Final C2 measured complete native start requests used 23 D1 statements/20 binding calls; tested independent presentation/final/retry requests used 12/9. A coached reading and each scribe readiness request used 12/9 individually; their three-request aggregate was 36/27. Durable Object local SQLite is a separate resource. C3/D3 must measure their own composed paths.

Small-rubric C2 samples measured native 90+1 authority 63,076 bytes and partial interrupted history 60,775 bytes; canonical completed six/twelve-player rooms measured 214,336/298,306 bytes. These are different representations and states. They do not establish worst-case size or full native 90 result size. The existing exporter 100KB SQL-literal guard must remain; D3 needs a supported bounded import path or an explicit unsupported-conversion result for larger records.

A later read-only size preflight ran the actual native validators, request-body reader, authoring parser, source-proof check and pure room engine with synthetic data. Permitted eight-part finals in a two-team 90-question room produced a 3,171,431-byte terminal projection; an admitted larger-rubric set produced 2,274,596 bytes at start. No HTTP handler or persistence was exercised by that probe. These values exceed the verified [D1 row limit](https://developers.cloudflare.com/d1/platform/limits/) and [SQLite Durable Object row limit](https://developers.cloudflare.com/durable-objects/platform/limits/), making real persistence regression and bounded storage a required C3 subtask. Binding large JSON as a SQL parameter cannot remove a row-size limit. The subsequent actual-runtime repair and remaining independent-review findings are described below.

The follow-up actual HTTP regression imported and published 91 larger questions and admitted twelve students through real room APIs, then failed start with HTTP 503 instead of 200. A later diagnostic run identified `SQLITE_TOOBIG`; the initial HTTP response alone did not establish that cause. The local repair uses `erudoza.practice-room/1` manifests and bounded immutable components, with atomic authority/outbox and complete history publication. Actual HTTP authored-start, 180-final persistence and restart/retry fixtures pass, including exact reconstruction of a 2,278,055-byte start and 3,206,981-byte terminal authority. Independent review still requires the ordinary connection-probe fix below before acceptance. Preserving an eager in-memory room does not prove that a bank of 91 maximum-sized rubrics or thousands of histories fits isolate memory; those larger capacity boundaries remain explicit limitations.

The exporter preflight also found that the actual canonical table is `PbeTrainingRecords`, with composite `(OrganizationId, Kind, Id)` identity. Its current generic archive mapping would collide for different kinds sharing an ID. D3 must preserve every original row, raw JSON keys and revisions, including oversized archives, and verify native operational resume rather than treating an archive count as equivalent. The proposed bound-parameter importer is not implemented or validated yet.
